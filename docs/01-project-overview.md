
# 1. Описание проекта

## 1.1. Общая информация

**Название:** Платформа государственной поддержки промышленности.

**Заказчик:** Минпромторг.

**Предметная область:** государственная поддержка промышленных предприятий.

**Тип проекта:** учебный проект по системному анализу.

**Статус:** проектирование.

## 1.2. Бизнес-контекст

Промышленные предприятия могут обращаться за государственной
поддержкой в рамках программ субсидирования и льготного
финансирования.

Рассмотрение заявок может включать сбор сведений о предприятии,
проверку документов, оценку соответствия условиям программы
и принятие решения уполномоченным сотрудником.

Проектируемая система должна автоматизировать отдельные этапы
этого процесса, обеспечить единое пространство для обработки
заявок и повысить прозрачность принимаемых решений.

Конкретные условия предоставления поддержки должны
определяться регламентом выбранной программы.

## 1.3. Цель проекта

Спроектировать систему автоматизации приёма, проверки
и рассмотрения заявок промышленных предприятий
на получение мер государственной поддержки.

## 1.4. Задачи проекта

1. Определить заинтересованные стороны и их потребности.
2. Описать процесс обработки заявки.
3. Определить бизнес-правила и условия проверки.
4. Сформировать функциональные требования.
5. Определить нефункциональные требования.
6. Спроектировать модель данных.
7. Описать взаимодействие компонентов и внешних систем.
8. Подготовить спецификацию API.
9. Разработать сценарии тестирования и критерии приёмки.

## 1.5. Границы проекта

### В рамках проекта

- Создание и подача заявки.
- Идентификация предприятия по ИНН.
- Получение сведений о предприятии через тестовый сервис.
- Проверка полноты и корректности данных.
- Проверка соответствия условиям программы.
- Формирование результатов автоматизированной проверки.
- Рассмотрение заявки уполномоченным сотрудником.
- Фиксация решения и истории изменения статусов.
- Уведомление заявителя о результатах рассмотрения.

### За рамками проекта

- Фактическое перечисление денежных средств.
- Юридически значимое заключение и подписание договоров.
- Промышленная интеграция с государственными системами.
- Обучение и внедрение полноценной модели искусственного интеллекта.

## 1.6. Основные допущения

1. Внешние источники данных представлены тестовыми сервисами.
2. Используются только вымышленные данные предприятий.
3. Условия предоставления поддержки задаются правилами
   конкретной программы.
4. Результаты автоматизированных проверок доступны сотруднику
   для анализа.
5. Решение фиксируется пользователем с соответствующими
   полномочиями.
6. Целевые показатели времени обработки требуют обоснования.

## 1.7. Ограничения

- Отсутствие доступа к промышленным государственным API.
- Отсутствие реальных персональных и конфиденциальных данных.
- Необходимость учитывать права доступа к сведениям
  о предприятиях.
- Отсутствие подтверждённых регламентов конкретной программы
  на начальном этапе проектирования.

## 1.8. Предварительные критерии успешности

- Описан полный жизненный цикл заявки.
- Определены роли и полномочия участников.
- Сформированы проверяемые требования.
- Разработана модель данных.
- Описаны контракты взаимодействия компонентов.
- Предусмотрены обработка ошибок и аудит действий.
- Для основных сценариев определены критерии приёмки.

## 1.9. Открытые вопросы

- Какие виды государственной поддержки входят в первую версию?
- Какие критерии допуска установлены выбранной программой?
- Какие сведения можно получить автоматически?
- Какие документы обязан предоставить заявитель?
- Какие решения вправе принимать сотрудник?
- Какие основания для отказа и ручной проверки предусмотрены?
- Какие сроки обработки установлены регламентом?
